Overview

The store follows Django's model–view–template structure, split into 4 apps: home for the landing and about pages, movies for the catalogue and reviews, accounts for sign-up and order history, and cart for the session cart and checkout.

Authentication uses Django's built-in auth rather than a hand-rolled one, which keeps password hashing and session handling out of my code. The cart lives in the session, so it survives navigation without needing a row in the database until an order is actually placed.

Approach

I built one feature per session and committed often, which meant a broken experiment was never more than a few minutes of work to unwind. When something didn't make sense — URL routing early on, then how to keep a cart in the session — I went to the course textbook and Django's own documentation rather than guessing, and recorded each session so I could go back over the parts that hadn't landed yet.
